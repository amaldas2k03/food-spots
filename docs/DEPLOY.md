# Deploying FoodSpots

The app deploys as three pieces:

| Piece | Host | Config |
|---|---|---|
| Web client (Vite SPA) | **Vercel** | [`client/vercel.json`](../client/vercel.json) |
| API server (Express + Socket.io) | **Render** | [`render.yaml`](../render.yaml) |
| PostgreSQL | **Neon** | connection string only |

Vercel can't host the API — Socket.io needs a persistent connection that
serverless functions don't provide — so the API lives on Render.

All three hosts deploy from GitHub, so **commit and push these config files first.**

---

## 1. Database — Neon

1. Create a project at <https://neon.tech> (free tier is fine).
2. Copy the **pooled** connection string (host ends in `-pooler.…neon.tech`).
   The pooler matters — it keeps Prisma from exhausting connections.
3. Make sure it ends with `?sslmode=require`. Keep it for step 2.

## 2. API server — Render

1. <https://dashboard.render.com> → **New → Blueprint** → pick this repo.
   Render reads [`render.yaml`](../render.yaml) and creates the `foodspots-api` service.
2. When prompted, fill the `sync: false` env vars:
   - `DATABASE_URL` — the Neon pooled string from step 1.
   - `CLIENT_ORIGIN` — leave blank for now (set it in step 4).
   - `GOOGLE_*` / `CLOUDINARY_*` — only if you want those features; blank disables them.
   - `JWT_SECRET` is generated automatically.
3. Deploy. The build runs `prisma migrate deploy`, creating the tables.
4. **Seed once** (optional sample data): open the service's **Shell** tab and run:
   ```bash
   npm run seed
   ```
5. Note the service URL, e.g. `https://foodspots-api.onrender.com`.
   Check `https://foodspots-api.onrender.com/api/health` returns `{ "ok": true }`.

> Free Render services sleep after ~15 min idle; the first request then takes
> ~30s to wake. Upgrade the plan to keep it always on.

## 3. Web client — Vercel

1. <https://vercel.com> → **Add New → Project** → import this repo.
2. Set **Root Directory** to `client`. Vercel auto-detects Vite from
   [`client/vercel.json`](../client/vercel.json) (build `npm run build`, output `dist`,
   plus the SPA rewrite so deep links don't 404).
3. Add **Environment Variables**:
   - `VITE_API_URL` — the Render URL from step 2, **no trailing slash**
     (e.g. `https://foodspots-api.onrender.com`). The client appends `/api` itself.
   - `VITE_MAPTILER_KEY` — for maps/heatmap (optional).
   - `VITE_GOOGLE_CLIENT_ID` — for Google sign-in (optional; must match the
     server's `GOOGLE_CLIENT_ID`).
4. Deploy. Note the URL, e.g. `https://foodspots.vercel.app`.

## 4. Connect the two (CORS)

The server only accepts requests from `CLIENT_ORIGIN`, so:

1. In Render, set `CLIENT_ORIGIN` to the exact Vercel URL from step 3
   (`https://foodspots.vercel.app`, no trailing slash) and redeploy.
2. Reload the Vercel site — API calls and live notifications should now work.

Using a custom domain on Vercel? Point `CLIENT_ORIGIN` at that domain instead.

## Environment variables at a glance

**Render (server)**

| Var | Required | Notes |
|---|---|---|
| `DATABASE_URL` | ✅ | Neon pooled connection string |
| `JWT_SECRET` | ✅ | auto-generated by the blueprint |
| `JWT_EXPIRES_IN` | | defaults to `7d` |
| `CLIENT_ORIGIN` | ✅ | the Vercel URL (set in step 4) |
| `GOOGLE_CLIENT_ID` | | Google sign-in |
| `GOOGLE_MAPS_SERVER_KEY` | | crawl route ETAs |
| `CLOUDINARY_*` | | review photo/video upload |

**Vercel (client)**

| Var | Required | Notes |
|---|---|---|
| `VITE_API_URL` | ✅ | Render URL, no trailing slash |
| `VITE_MAPTILER_KEY` | | maps + heatmap |
| `VITE_GOOGLE_CLIENT_ID` | | Google sign-in |

## Redeploys

Both hosts auto-deploy on push to `main`. Schema changes ship automatically
because the Render build runs `prisma migrate deploy` each time.
